# 全新服务器发布：不迁移本机业务数据

本机的任务、聊天、个人 Key、员工自定义配置、成片和数据库应继续留在本机。
服务器发布程序源码、正式界面素材、默认技能目录和经校验的公共技能安装包。
新用户自行注册或通过平台登录，再配置自己的 Key 和工作空间。

## 生成干净源码包

在项目根目录运行（输出文件必须不存在，且位于项目目录之外）：

```sh
python3 scripts/export-clean-source.py ../releases/wishtaday-clean-source.tar.gz
```

脚本读取 Git 跟踪的工作区文件，并加入本说明和导出脚本；不会递归复制本机目录。
公共技能 ZIP 不随默认发布包分发；首次安装时按固定快照下载并校验 SHA-256。
这些是技能库安装功能需要的产品资源，不是用户的技能绑定或任务数据。
包中附有 RELEASE-CONTENTS.json，供核对文件清单和校验值。
脚本拒绝私有路径、密钥文件、数据库备份、符号链接以及覆盖已有输出。
新增未跟踪的源码需要先纳入版本管理，才会进入以后的包。

不要上传整个本机项目目录，不要上传 .local、.env、outputs、RESTORE-KEY.json，
不要恢复本机数据库或媒体备份，不要复制本机 operations-config.key。
Docker 的排除规则还会排除本地状态、开发缓存和设计原稿；正式角色素材保留在
apps/web/public 中。源码包保留受版本管理的设计文件，以支持现有角色一致性测试。

## 服务器首次安装

1. 使用全新的、独立的数据库和媒体存储；复用旧卷或旧数据库不会自动变成空白。
2. 按部署要求新建服务器密钥、数据库账号及连接配置，不复用开发机配置文件。
3. 只执行结构迁移及正式部署步骤，不运行本地演示初始化或恢复脚本。
4. 通过平台登录创建工作空间，确认任务、聊天和个人 Key 初始为空。
5. 用户自行保存个人 Key，验证隔离后再开放使用。

此包是源码交付包，并非已经启动成功的云端安装。数据库、缓存、视频服务及平台身份
认证仍需在服务器分别接通。当前主 Docker 镜像不打包 AiToEarn 独立服务。
新的发布仓库为 https://github.com/davidll8819/4yi_opc ，使用 main 分支。
102 个公共技能 ZIP 保存在历史固定快照中，当前发布目录及镜像不包含它们。
主通道使用 raw.githubusercontent.com，备用通道使用 api.github.com，分别固定到提交编号和文件编号，并验证同一 SHA-256。它们是不同下载线路，不是独立异地备份；GitHub 仓库必须保留。
原作者链接保留作来源记录，不自动追踪 HEAD。更新须显式更新目录、版本和校验值。
下载最多每条线路 45 秒、64 MB，禁止重定向及任意下载主机。校验后仍走原有安装与
工作空间隔离逻辑，不执行安装包脚本。已有本机 ZIP 继续作为离线回退；已安装的
技能保存在原有工作空间存储中，无需每次执行重新下载。

## 独立视频 Linux 镜像

在仓库根目录构建：

```sh
docker build -f integrations/aitoearn/source/project/aitoearn-backend/Dockerfile.production -t wishtaday-video:local integrations/aitoearn/source/project/aitoearn-backend
```

采用 Node.js 24 和 pnpm 10.33.0，按锁定文件构建，再仅安装生产依赖。
同一镜像分别以 VIDEO_SERVICE=ai 和 VIDEO_SERVICE=server 启动两个服务；
VIDEO_CONFIG 必须指向挂载的绝对配置路径，工作目录 /work 用于独立运行文件。
镜像自带 FFmpeg 和中文字体，不携带真实配置或用户数据。

已经验证：两个后台及 15 个依赖模块的 Linux 编译、两个应用入口加载、Sharp 图片处理、
H.264/AAC 测试视频编码；主应用 Windows/Linux 回归和主镜像构建也已通过。
尚未验证：完整 Linux 服务启动与数据库、缓存、私有对象存储的联调，真实模型生成及
新用户从注册到成片的完整云端流程。视频服务 /health 在当前企业模式下需要身份认证，
平台的健康探测方式也需要适配，不能把入口加载检查当成已通过线上健康检查。

当前 4yi-app.json 只声明 web；本次没有修改平台后台、自动发布镜像或创建付费云资源。

清理缓存不会修复云平台的 CPU／内存调度不足；这两项要分别处理。

备用 GitHub 文件接口使用匿名公共读取，受 GitHub 请求额度限制；额度耗尽时会提示重试。
两个通道不是独立存储灾备，后续可将相同校验文件迁移到独立对象存储，再调整服务器端白名单。
历史提交仍包含 ZIP，因此完整 Git 历史不会缩小；部署应使用当前分支的浅克隆或源码归档。
